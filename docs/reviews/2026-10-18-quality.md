## Math practice

**High.** File: `games/math-practice/index.html`, `stepGaze` around lines 1247–1278, and the `leave-grace` case around lines 1912–1923.

What is wrong: An in-progress look that leaves its button, or moves to a different button, is kept for `LEAVE_MS` (280 ms). Elapsed stays `now - dwellStart` through that gap, and the ring keeps filling while the look is off the card. A return before 280 ms only clears `dwellOffAt`. It does not move `dwellStart`. If wall time since entry is at least 650 ms, that return step fires the card.

Why it matters: A card commits after 650 ms on that card. A look that rests for 640 ms, slips off, and comes back fires. A look that rests for 500 ms and is away for 200 ms fires on the way back. The math spec says the visit is discarded on the step the look leaves, time off the card does not count, and `LEAVE_MS` is only a spelled constant. `family-play-dwell` uses one continuous look, so a 640 ms stay still passes. `leave-grace` fails the run if the dwell drops on the slip step, checks the ring only on that slip step, and never returns to the card, so it cannot catch this commit. A cancel-on-leave fix fails that case as written.

Fix: When the hit is missing or is a different button, call `clearDwell()` in that same `step`. Keep `LEAVE_MS` as a declared constant and stop using it in the dwell math. Leave the wrong-card cooldown as a writer flag that clears when the look leaves; that part of `stepGaze` is already separate. Rewrite `leave-grace` so the slip step leaves `dwell()` at 0 and `filled` null, and so 500 ms on the card, a gap under 280 ms, and a return still leave `filled` null. Keep `family-play-dwell` as the continuous 640 / 649 / 650 / 660 proof.

## Maze

**High.** File: `games/maze/index.html`, `stepGaze` around lines 1356–1392, and the `leave-grace` case around lines 2117–2157.

What is wrong: A look that slips from a lit stone onto empty space is kept for 280 ms. The first off step stores `heldElapsed = now - dwellStart`, which includes the gap after the last on-button step. A return inside 280 ms sets `dwellStart = now - heldElapsed` and then fires when that stored value is at least 650 ms. A move onto a different button does reset immediately.

Why it matters: The maze spec says `LEAVE_MS` is declared and is not a leave grace. The next `step` off the stone, including a move onto the floor, drops the dwell. Adding the grace is a second timer. A last on-button sample at 640 ms, an off sample at 656 ms, and a return inside 280 ms walks the token, because 656 was stored as contact. `leave-grace` requires the ring to survive the floor step and requires the returned look to walk at `step(46750)`. That case fails a cancel-on-leave fix, and it never steps a 640 ms sample that leaves. `move` and `mazeWalk` still reject an unlit id and a non-neighbor; this bug is only the dwell.

Fix: When `key` is missing or differs from `dwellKey`, call `clearDwell()` on that step. Delete the `heldElapsed` restore. Rewrite `leave-grace` so the floor step leaves `dwell()` at 0 and `token` unchanged, and so coming back is a new visit whose entry step does not walk.

## Flash cards

**High.** File: `games/flash-cards/index.html`, `advanceTrial` around lines 1333–1346 and `stepGaze` around lines 1745–1758.

What is wrong: The show beat calls `advanceTrial` without `clearVisit()`. `#prompt` and the choice buttons are the same elements on the next trial, and `stepGaze` keeps `visit.elapsed` while `visit.btn` is that element. The following step adds the new frame and clicks once elapsed reaches 650 ms. `hear()` speaks the current `prompt` whenever the screen is still `trial`. `onChoice` runs because the new trial is `ask`, and a print face speaks that choice before `choose`. A visit that already fired during show stays fired on that same element, so a continued look never starts the next dwell.

Why it matters: The spec keeps those buttons through the 800 ms beat, then advances even when a dwell is unfinished, and that unfinished dwell does not speak. Advance deals the next trial and does not speak. A look with 640 ms on the shown word at the beat speaks the next prompt about 10 ms later. A look with 600 ms on a choice during show chooses that slot on the next trial. `speech-on-dwell` stays inside one trial, so it stays green. `dealCurrent`, `subject`, and `choose` do not speak on their own, and `speakWord` still returns unless the string is in the subject's word list. The inner `hear-picture` branches in `render` are unreachable; the live horn path is the `else`, so those branches do not hide this bug.

Fix: Call `clearVisit()` on both paths inside `advanceTrial`. `step` already runs `stepGaze` before `advanceTrial`, so a dwell that reaches 650 ms on the show step can still `hear` the shown word, and the clear then drops whatever is left. Leave the buttons in the page. Leave `said` as it was. The next `stepGaze` starts a new visit and does not commit on the entry step. Add a check that puts 640 ms on `#prompt` during show, advances at 800 ms, and asserts that 30 ms later `lastChoice` is null and `said` is unchanged, then asserts that a fresh 660 ms on that same button may speak the new prompt.
