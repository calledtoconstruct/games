# Puzzle engines

**Author.** Puzzle-engine member, design committee.

**Date.** 2026-10-18.

**Status.** Accepted for the generator and the headless checks. The page hooks, screens, and gaze timings stay in `2026-10-18-architecture.md` and `2026-10-18-gaze.md`. This memo does not add a second dwell, a second socket, or a second script.

The five games need a deterministic core another programmer can implement and test without a browser. The functions below are pure. The same arguments return the same value. They do not read the clock, the DOM, the query string, the network, or `speechSynthesis`. They live in the page script. There is no shared file.

Band ids, matching the menu buttons: `tiny`, `little`, `shop`, `rush`.

## Picks where the sources disagree

These are engine rulings. A later spec may not loosen a check to make a prettier algorithm pass.

1. **Sudoku holes are dug from a shuffled completion, balanced across boxes, and stopped at the given floor.** Uniqueness is a search that stops at two solutions. The technique check is naked singles, or naked plus hidden singles, as the band says. No dancing links and no 17-clue target. A 9×9 is an engine result; the page hides it when a cell would be under 72 px.

2. **Math is one blank and one integer solution.** Cards always include that integer exactly once, and no other card satisfies the equation. Little Pals unlocks a missing second addend only after one correct result. Shopkeeper families do not mix inside a stretch. The sum distractor is required for a `+` or `−` part-blank, and the generator may only emit a part-blank whose sum sits in range.

3. **Word search does not use an English dictionary.** The only extra words are the seven-term denylist below. Tiny Tots is **3 rows by 5 columns**, not 4×3. Three-letter words on a 3-column row cannot share a cell, and the foods chain needs five columns (`BUN` + `NUT`). Five columns at 73 px are already inside the gaze size table and above the 72 px floor. Little Pals is **5 rows by 4 columns**. Overlap is a shared cell, required on every band because these widths allow it. An overlap ratio under 1.15 does **not** reject a grid that already shares a cell and has one span per word. That matches the architecture note and keeps the search inside a few milliseconds.

4. **Flash-card direction uses the architecture enum**, not the gaze memo's picture-then-word for the youngest bands. `hear-picture` means the prompt is a word the child may dwell to hear, and the choices are pictures. Speech on appear stays forbidden; that is the page. The gaze line that makes Tiny Tots "picture, then word, no reverse" would fail the accepted `tiny-two-pictures` check. Foils are always from the same subject. Tiny Tots foils are a different cluster.

5. **A maze solution's promised length is the number of dwells after straight runs collapse.** A corner stays a stone. Collapsing corners too makes 4–7 dwells impossible with only one or two one-cell dead ends, because each extra decision needs a branch. A full-rectangle growing tree also misses the dead-end lengths (measured: spurs of many cells, not one). The builder is a newest-cell self-avoiding walk plus straight spurs. It is a tree, so there is one route. It is not Sidewinder, not binary tree, and not braided. Little Pals is **5×5 only**. Rush tries **10×10, then 12×12**. A 4×4 and an 8×8 do not pass stone separation inside the try cap. Tiny Tots does not compress: each next cell is one dwell, and only that next cell is lit.

## Shared RNG

`makeRng(seed)` takes a uint32. `rngUint(rng)` returns the next uint32. Implement it in JavaScript with `Math.imul` exactly as follows. `>>>` is the unsigned shift. `imul(x, y)` is `Math.imul`.

1. `state = seed >>> 0`.
2. `state = (state + 0x6D2B79F5) >>> 0`.
3. `t = imul(state xor (state >>> 15), state or 1)`.
4. `t = t xor (t + imul(t xor (t >>> 7), t or 61))`.
5. Return `(t xor (t >>> 14)) >>> 0`.

`rngInt(rng, lo, hi)` is `lo + (rngUint(rng) % (hi - lo + 1))`, both ends included. `rngShuffle(rng, items)` copies the array and runs Fisher-Yates from the last index down to 1: swap `i` with `rngInt(rng, 0, i)`.

Seed 1 must yield these first four uints, in order: `0xA087EAF3`, `0x00B349C9`, `0x8706C4EB`, `0xFB2627FD`.

`playSeed(clockMs, counter)` is `imul( (clockMs >>> 0) xor imul(counter >>> 0, 0x9E3779B9), 0x85EBCA6B ) >>> 0`. `playSeed(1, 1)` is `0x3B230FE8`. The pure generators never call this. The page does, when `seed(n)` was not called: `clockMs` is `Date.now()`, and `counter` starts at 1 and increases by 1 for each generate in the page session. Self-check passes a fixed seed and does not read the clock. `seed(n)` on the page pins the next generate only, as the architecture memo already says.

`choiceSeed(seed, index)` is `imul(seed xor (index + 1), 0x9E3779B1) >>> 0`. Flash cards use it so one trial can be rebuilt without replaying earlier shuffles.

## Sudoku

### API

`sudokuGenerate(band, size, seed)` → `{ band, size, puzzle, solution, givens, fallbackUsed }`.

- `size` is 4, 6, or 9. `tiny` and `little` are size 4. `shop` is size 6. `rush` may be 6 or 9. The page picks 6 when a 9×9 cell would be under 72 px. The engine still generates a 9 when asked.
- `puzzle` and `solution` are row-major arrays of length `size * size`. Symbols are `1..size`. An empty puzzle cell is `0`. Row 0 is the top. Index `r * size + c`.
- `givens` is the count of non-zero puzzle cells.
- `fallbackUsed` is false when a dug grid passed, true when the constant below was returned.

`sudokuCandidates(size, grid, index)` → ascending symbols from `1..size` that are not already in that cell's row, column, or box. A filled cell returns `[]`.

`sudokuCountSolutions(size, grid)` → `0`, `1`, or `2`. It never counts past 2.

`sudokuSolveSingles(size, grid, mode)` → a completed grid, or `null`. `mode` is `"naked"` or `"both"`.

`sudokuOpeningNaked(size, grid)` → true only when every empty cell currently has exactly one candidate. Placing them is not required for this predicate.

### Boxes

| Size | Box | Box index |
| --- | --- | --- |
| 4 | 2 rows by 2 columns | `floor(r / 2) * 2 + floor(c / 2)` |
| 6 | 2 rows by 3 columns | `floor(r / 2) * 2 + floor(c / 3)` |
| 9 | 3 rows by 3 columns | `floor(r / 3) * 3 + floor(c / 3)` |

### Bands

| Band | Size | Givens | Technique | Extra |
| --- | --- | --- | --- | --- |
| `tiny` | 4 | exactly 12 | Every empty is a naked single on the opening grid, all at once | At least 3 distinct symbols |
| `little` | 4 | 8 through 10 | Naked singles only, as a chain. A hidden single must not be required | At least 3 distinct symbols |
| `shop` | 6 | 24 through 28 | Naked singles, then hidden singles. No guess | At least 5 distinct symbols. Every row has at least 4 givens |
| `rush` | 6 | 18 through 22 | Same as shop | At least 5 distinct symbols |
| `rush` | 9 | 40 through 48 | Same as shop | At least 8 distinct symbols |

Empties are spread across boxes: the fullest box has at most one more empty than the emptiest box. Stop at the floor (12, 8, 24, 18, or 40). Do not aim for a minimal puzzle. A dig that lands inside the window is legal. Seeds 1 and 2 land on the floor.

### Completion

The base value at row `r`, column `c` is `(boxCols * (r % boxRows) + floor(r / boxRows) + c) % size + 1`, with `boxRows` and `boxCols` from the table. That grid is a full valid sudoku.

`fillComplete(size, rng)` copies it, then, in this order:

1. Shuffle symbols `1..size` and replace every value.
2. Inside each horizontal band of `boxRows` rows, top band first, shuffle those row indices.
3. Shuffle the band order and apply it.
4. Inside each vertical stack of `boxCols` columns, left stack first, shuffle those column indices.
5. Shuffle the stack order and apply it.

These moves preserve rows, columns, and boxes. A broken completion is a bug, not a retry.

### Dig

One rng stream from `makeRng(seed)` covers every attempt.

1. Repeat up to 8 times.
2. `solution = fillComplete(size, rng)`. Copy it into `puzzle`.
3. `order = rngShuffle` of the cell indices `0 .. size*size-1`.
4. Repeat while a pass still clears a cell:
   - Let `minC` be the smallest number of empties currently in any box.
   - If givens are already at the floor, stop.
   - Walk `order`. Skip a filled cell whose box does not currently have `minC` empties.
   - Clear it on trial. Keep the clear only when all of the following hold. Otherwise put the symbol back.
     - Distinct symbols still meet the band minimum.
     - Shop only: no row has more than 2 empties.
     - The band technique still solves this grid to `solution` (`sudokuOpeningNaked` for tiny; `sudokuSolveSingles(..., "naked")` for little; `sudokuSolveSingles(..., "both")` for shop and rush).
     - `sudokuCountSolutions` returns 1.
5. Accept the attempt when givens are inside the band window, the box spread holds, the distinct-symbol minimum holds, the shop row rule holds, the technique solves to `solution`, and the solution count is 1. Otherwise start another attempt.
6. If all 8 attempts fail, return the fallback below and set `fallbackUsed`. Do not dig again.

### Solvers

**Candidates.** As in `sudokuCandidates`.

**Count.** Recursive search. Each call counts as one node. Past 600 nodes, return 2, which rejects the removal. Pick the empty cell with the fewest candidates; tie goes to the lowest index. Try those candidates in ascending order. An empty candidate list on that cell returns 0 for the branch. A full grid returns 1. Add the branches and stop the whole count at 2.

**Naked chain.** Scan indices from 0. Place the first cell whose candidate list has length 1. Restart from the top. If no naked single remains and an empty remains, return null for mode `"naked"`.

**Hidden single, mode `"both"` only.** Units in this order: rows `0..size-1`, then columns `0..size-1`, then boxes `0..size-1`. Inside a unit, symbols `1..size`. A hidden single is a symbol missing from the unit with exactly one empty cell in that unit whose candidates include it. Place the first one found, then restart from naked singles. If a pass places nothing and an empty remains, return null.

Little Pals must finish in naked mode. Shop and Rush may use a hidden single. Neither may leave a cell for a guess.

### Checks

For `sudokuGenerate(band, size, 1)` and seed 2, on each row of the band table:

- `fallbackUsed` is false.
- `sudokuCountSolutions(puzzle)` is 1, and filling the holes as `solution` does not contradict a given.
- The technique for that band returns `solution`.
- Givens are inside the window. Distinct symbols meet the minimum. Box empty-counts differ by at most 1.
- Tiny: `sudokuOpeningNaked` is true, and every empty cell's candidate list has length 1.
- Little: `sudokuSolveSingles(puzzle, "naked")` equals `solution`.
- Shop: every row has at least 4 non-zero cells. Mode `"both"` finishes. The solution count is 1, so no guess is required.
- Rush 9: at least 8 distinct digits and at least 40 givens.

## Math

### API

`mathCap(band)` → tiny 4, little 6, shop 8, rush 10.

`mathCardCount(band)` → tiny 2, little 3, shop 4, rush 4.

`mathMake(band, seed, index, history)` → one problem, or `null` if `index` is outside `0 .. cap-1`.

`history` is the list of problems already answered correctly. Each entry is `{ blank }` where `blank` is the field below. The page appends only after a correct card. A wrong card does not call `mathMake` again. Misses are not stored.

`mathAccepts(problem, value)` → true when `value` is the unique completion.

A problem is:

- `kind`: `"quantity"` or `"equation"`.
- `op`: `null`, `"+"`, `"-"`, `"×"`, or `"÷"`.
- `a`, `b`, `c`: numbers or `null`. An equation has exactly one `null`, and that null is the blank. A quantity stores the shown count in `a` and leaves `b` and `c` null.
- `blank`: `"set"`, `"more"`, `"result"`, `"part"`, or `"start"`.
- `answer`: the integer that belongs in the blank.
- `cards`: shuffled integers. Length is `mathCardCount(band)`.
- `layout`: `"pictures"`, `"right"`, or `"left"`. Right means `a op b = c`. Left means `c = a op b`. Pictures mean no operator glyph.
- `repeats`: `1`, or `3` for the shopkeeper `k + k + k` line.
- `range`: inclusive `[lo, hi]` of integers the cards may use.

`mathAccepts` substitutes `value` for the null and evaluates in integers. Division accepts only when the dividend is exactly `divisor * quotient`. A quantity `"set"` accepts only `value === a`. A quantity `"more"` accepts only `value === a + 1`. A repeat accepts only `value === 3 * a`.

### Schedule

Rng for a problem is `makeRng(choiceSeed(seed, index))`, so each index is stable.

**Tiny.** Index even: `blank` `"set"`, `a = rngInt(1, 3)`, `answer = a`. Index odd: `blank` `"more"`, `a = rngInt(1, 2)`, `answer = a + 1`. `kind` `"quantity"`, `layout` `"pictures"`, `op` null, `range` `[1, 3]`. Cap 4.

**Little.** Totals stay in `0..5`. `layout` is always `"right"`. `blank` is never `"start"`.

| Index | Shape |
| --- | --- |
| 0 | `+`, result |
| 1 | `−`, result |
| 2 | `+`, result |
| 3 | part, but only if `history` contains a result; otherwise `+` result |
| 4 | `−`, result |
| 5 | part, but only if `history` contains a result; otherwise `−` result |

A little part is only `a + □ = c`. It is never the first slot and never subtraction.

**Shop.** One family per stretch. No `×` or `÷`. Index 7 is the repeated addend, still not multiplication.

| Index | Family | Range | Op | Layout |
| --- | --- | --- | --- | --- |
| 0, 1 | result | 0..10 | `+` then `−` | right |
| 2, 3 | part | 0..10 | `+` then `−` | right |
| 4, 5 | start | 0..10 | `+` then `−` | left |
| 6 | result | 0..20 | `+` | right |
| 7 | repeat result | 0..20 | `+`, `repeats` 3 | right |

**Rush.** Addition and subtraction stay in `0..20`. Factors are one digit. Division is exact. The first times and divide problems use only the factor set A.

| Index | Op | Blank | Factors or range | Layout |
| --- | --- | --- | --- | --- |
| 0 | `+` | result | 0..20 | right |
| 1 | `−` | result | 0..20 | right |
| 2 | `×` | result | set A | right |
| 3 | `÷` | result | set A | right |
| 4 | `×` | part | set B | right |
| 5 | `÷` | part | set B | right |
| 6 | `×` | start | set C | left |
| 7 | `÷` | start | set C | left |
| 8 | `+` | part | 0..20 | right |
| 9 | `−` | start | 0..20 | left |

Factor sets, ascending: A is `1, 2, 5, 10`. B is `1, 2, 3, 4, 5, 10`. C is `1..10`.

### Operand pools

Sort every pool by the first component, then the second. Choose `rngInt(0, pool.length - 1)`. Pools below are non-empty; an empty pool is a bug, and the function must not invent a negative.

`S` is 5 for little, 10 or 20 as the schedule says.

- **Add result.** Pairs `(a, b)` with `a, b >= 0`, `a + b <= S`, not both 0. `c` is null. `answer = a + b`.
- **Subtract result.** Pairs `(a, b)` with `0 <= b <= a <= S`, not both 0. `c` is null. `answer = a - b`.
- **Add part.** Pairs `(a, c)` with `0 <= a <= c <= S`, `answer = c - a`, `sum = a + c` inside the card range, and `sum !== answer`. `b` is null.
- **Subtract part** (shop and rush only). Pairs `(a, c)` with `0 <= c <= a <= S`, `answer = a - c`, `sum = a + c` inside the card range, and `sum !== answer`. `b` is null.
- **Add start.** Pairs `(b, c)` with `0 <= b <= c <= S`, not both 0. `a` is null. `answer = c - b`.
- **Subtract start.** Pairs `(b, c)` with `b, c >= 0` and `answer = b + c <= S`, not both 0. `a` is null. Equation `□ − b = c`.
- **Times result.** Pairs `(f, g)` from the factor set. `a = f`, `b = g`, `c` null, `answer = f * g`. Card range `[1, 100]`.
- **Times part.** `a × □ = c`. Pairs `(f, g)` from the set with `answer = g`, `c = f * g`, and `sum = f + c` inside `[1, 10]` and not equal to `g`. Card range `[1, 10]`.
- **Times start.** `□ × b = c`. Pairs `(f, g)` from the set. `b = g`, `c = f * g`, `answer = f`. Card range `[1, 10]`.
- **Divide result.** `a ÷ b = □`. Same pairs. `a = f * g`, `b = f`, `answer = g`. Card range `[1, 10]`.
- **Divide part.** `a ÷ □ = c`. `a = f * g`, `c = g`, `answer = f`, and `sum = a + c` inside `[1, 10]` and not equal to `f`. Card range `[1, 10]`.
- **Divide start.** `□ ÷ b = c`. `b = f`, `c = g`, `answer = f * g`. Card range `[1, 100]`.
- **Repeat.** `k = rngInt(1, 6)`, `a = b = k`, `c` null, `answer = 3k`, `repeats` 3, range `[0, 20]`. The page shows `k + k + k = □`.

No compare story, no two-step story, no parentheses, no remainder.

### Cards

Card range is the problem's `range`. Build the list in this order, then `rngShuffle` it.

1. Push `answer`.
2. Push the neighbor: `answer + 1` if that value is inside the range, otherwise `answer - 1`. The band ranges always contain one of those.
3. If `blank` is `"part"` and `op` is `"+"` or `"−"` or `"×"` or `"÷"`, push the sum of the two visible numbers when it is inside the range and not already in the list. The pools above make that sum legal for every part-blank, so the card is always present.
4. Let `pool` be the other integers in range, ascending. While the list is shorter than the band's card count, take the next pool value, starting at `rngInt(0, pool.length - 1)` and wrapping once. Then stop. Do not wrap onto a duplicate.

Every card is an integer in range. Cards are distinct. Negatives never appear. Tiny cards are only `1`, `2`, or `3`.

### Checks

Use seed `11`. Build history by appending each problem's `blank` after a correct accept, then request the next index.

- For every band and every index, exactly one integer in `range` makes `mathAccepts` true, that integer is `answer`, and `cards` contains it once. No other card makes `mathAccepts` true. Card length matches the band. All cards are inside `range`.
- Tiny: `kind` is `"quantity"`, `layout` is `"pictures"`, `op` is null, values are `1..3`, there is no `+`, `−`, `×`, `÷`, or `=` for the page to print. Cap 4 returns null on the next call.
- Little, history empty: indices 0, 1, and 2 are `"result"`. Index 3 is `"result"`, not `"part"`. No index is `"start"`. `layout` is `"right"`. Every total `a + b`, `a - b`, or part total is at most 5. Three cards.
- Little, after one result is in history: index 3 is `"part"` and the op is `"+"`. One card is the sum of the two visible numbers.
- Shop: the families follow the index table with no mixed stretch. `op` is never `"×"` or `"÷"`. No card is above 20. Index 7 has `repeats` 3 and `answer === 3 * a`.
- Rush indices 2 and 3: both factors that are printed, and the answer when the blank is a factor, are in set A. Index 4 uses set B. Index 6 uses set C.
- A part-blank's cards include the sum of the two visible numbers.
- `mathMake` at `index === cap` returns null.

## Word search

### API

`wordHygiene(words)` → `{ ok, reason }`. `reason` is `""` when `ok` is true, otherwise one of `empty`, `alphabet`, `duplicate`, `substring`.

`wordSpans(grid, word)` → how many distinct cell-sets spell `word`.

`wordSearchGenerate(group, seed, harder)` → `{ ok, grid, placements, fallbackUsed, directions }`.

`group` is `{ id, band, rows, cols, words, directions, fallback }`. `words` are uppercase. `fallback` is an array of row strings, one character per column. `harder` is false unless the page saw the `harder` flag, and it changes Rush only.

Directions and deltas, row increasing downward:

| Name | Delta |
| --- | --- |
| `right` | `0, +1` |
| `left` | `0, -1` |
| `down` | `+1, 0` |
| `up` | `-1, 0` |
| `downRight` | `+1, +1` |
| `downLeft` | `+1, -1` |
| `upRight` | `-1, +1` |
| `upLeft` | `-1, -1` |

Play directions:

| Band | Rows × cols | Words | Lengths | Directions |
| --- | --- | --- | --- | --- |
| `tiny` | 3 × 5, fixed | 3 | 3 | `right` |
| `little` | 5 × 4, fixed | 4 or 5 | 3 or 4 | `right` |
| `shop` | 6 × 6, fixed | 6, 7, or 8 | 4 or 5 | `right`, `down` |
| `rush` | 6 × 6, grow once to 7 × 6 | 8 | 4 through 7 | `right`, `down`, `downRight`, `downLeft` |

`harder` on Rush adds `left`, `up`, `upLeft`, `upRight` to the play set. The span scan is always all eight, harder or not. A 7-letter word does not fit in 6×6; the grow step exists for that word. Do not add a column past 6.

### Denylist

After filler, each of these has **zero** spans. There is no other dictionary.

`ASS`, `FAG`, `FUK`, `NIG`, `SEX`, `TIT`, `CUM`.

### Hygiene

Reject, and do not retry, when any of these fail.

1. The list is non-empty. Every word matches `A`–`Z` with no space and no lowercase.
2. No duplicates.
3. For two different words `A` and `B`, `A` is not a contiguous substring of `B` and not a contiguous substring of the reverse of `B`. `RAT` with `TAR` fails. `CAT` inside `CATCH` fails. One palindrome, such as `EYE` or `MOM`, is allowed, because the reverse is the same word and the rule is about two different words.

### Spans

A span is the set of cells, not the direction. Scan every start cell and all eight deltas. When the letters match, record the set. Canonical key: cell indexes `r * cols + c`, sorted ascending, joined. Forward and backward reads of a palindrome share a key and count once. `wordSpans` is that set's size.

### Generate

1. Run hygiene. On failure return `{ ok: false }` immediately.
2. Start at the group's `rows` and `cols`.
3. From `makeRng(seed)`, assign each word a random key. Sort by length descending, then by that key ascending.
4. Search. A placement attempt is one candidate tried. Cap **4000** attempts at this size.
   - List every in-bounds start and every play direction. A candidate is legal when every filled cell it touches already equals the letter it needs. Score is the number of those shared cells.
   - Sort by score descending. Shuffle ties with the rng, and do not reorder across different scores.
   - Place the word, recurse to the next word, and restore the cells on failure.
   - At a full placement, reject it (restore and keep searching) unless every answer has `wordSpans === 1` and at least two words share a cell. Do not reject for occupancy. Do not reject for an overlap ratio under 1.15.
5. Filler. Collect empty cells. Up to 30 times, shuffle those cells and, for each, shuffle `A`–`Z`. Keep the first letter that leaves every answer at exactly one span and every denylist word at zero spans. If a cell has no such letter, that restart fails. If all 30 fail, the placement is rejected and the search backtracks, still inside the 4000 cap.
6. If the cap hits with no filled grid: on Rush, if the grid is still 6×6, add one row (7×6) and repeat steps 3–5 once with a fresh `makeRng(seed)` and a fresh 4000 cap. Tiny, Little, and Shop do not grow. A second failure uses the stored fallback.
7. Accept the fallback only when hygiene already passed and the fallback grid itself has one span per answer, zero denylist spans, and at least one shared cell. Otherwise `{ ok: false }`. The page must not show that.

`placements` is `{ word, row, col, dir }` for the reading direction, which is always in the play set. The two endpoints are the first cell and the cell `length - 1` steps along `dir`. The page may commit either order. The engine does not score a bank id.

## Maze

**Superseded 2026-10-19.** A later play request replaced the straight short spurs described below. Little Pals, Shopkeeper, and Rush now grow one bent dead end that is longer than the remaining way out. Other spurs stay shorter than that remainder. Corner cells on a wrong path are stones, and the walk is stop to stop. Tiny Tots sometimes adds one bent wrong turn on the 3×3. The tree, one route, grid sizes, and dwell windows stay. See "Branches revised 2026-10-19" in the maze design spec. Do not treat the straight-spur steps below as the current builder.

### API

`mazeGenerate(band, seed)` → `{ band, rows, cols, cells, edges, start, goal, stones, solution, deadEnds, fallbackUsed }`.

- `cells` is the open floors, each `"r,c"`.
- `edges` is unordered pairs of orthogonally adjacent cells, each pair stored once as the two ids in row-major order joined by `"|"`.
- `start` and `goal` are cell ids.
- `stones` is the dwell points, a subset of `cells`.
- `solution` is the stone ids from start to goal.
- `deadEnds` is `{ id, length }` for each dead-end leaf.
- A stone id is `"r,c"` with no spaces. Row 0 is the top.

`mazeLit(maze, stoneId)` → the set of stone ids that are legal dwells from that stone.

`mazeWalk(maze, fromId, toId)` → the cell ids from `fromId` through the open corridor to `toId`, both ends included, or `null`.

`mazeSolution(maze)` → the stone ids of the unique start-to-goal route. `solution.length - 1` is the promised length.

### What a stone is

On Tiny Tots every open cell is a stone. The promised length is the number of steps between cells.

On the other bands, a cell is a stone when it is the start, the goal, a dead-end leaf, a branch (three open neighbors), or a corner. A corner is a degree-2 cell whose two neighbors are not opposite. Opposite means one step north and one step south, or one step east and one step west. A straight degree-2 cell is the inside of a corridor and is not a stone. One dwell walks that whole straight run. A bend is a new dwell. That is the ruling in the picks.

Chebyshev distance is `max(|r1-r2|, |c1-c2|)`.

### Bands

| Band | Grid | Solution dwells | Dead ends | Lit |
| --- | --- | --- | --- | --- |
| `tiny` | a straight `1 × N`, or a simple path on a `3×3` | 2, 3, or 4 | 0 | exactly 1, the next cell toward the goal, until the goal |
| `little` | `5×5` only | 4 through 7 | 1 or 2, each length 1 | every stone-neighbor, and never more than 3 |
| `shop` | `6×6`, then `8×8` | 8 through 14 | 3 through 6, each length 1 through 3 | at most 3 |
| `rush` | `10×10`, then `12×12` | 12 through 20 | 6 through 12, each length 1 through 5, and at least 2 of those lengths are 3, 4, or 5 | at most 3 |

Dead-end length is the number of open cells from the branch to the leaf, not counting the branch. A one-cell spur has length 1.

`4×4` is not used. Co-lit stones there fail Chebyshev distance 2 inside the try cap. `8×8` is not used for Rush for the same reason plus the long-spur quota. A full-rectangle growing tree is not used: its dead ends are many cells long, so it cannot hit this table. Sidewinder, the binary-tree algorithm, and braided loops are rejected. The graph is a tree: connected, and `edges.length === cells.length - 1`. Routes = 1.

### Tiny build

`rng = makeRng(seed)`.

1. `dwells = rngInt(rng, 2, 4)`.
2. If `rngInt(rng, 0, 1)` is 0, lay a straight row `(0,0) … (0, dwells)` on a `1 × (dwells + 1)` grid. A dwell of 4 is five cells. The research "three or four cells" covers dwells 2 and 3; the check window includes 4, so five cells are allowed.
3. Otherwise grow a self-avoiding walk of `dwells + 1` cells on a `3×3`. Shuffle the free orthogonal neighbors and step. If the walk sticks before that length, restart, up to 20 times. If those fail, use the straight row. That is still a generated maze, not the fallback.
4. Edges join consecutive path cells. Stones are every path cell. `mazeLit` on a cell that is not the goal returns only the next path cell toward the goal. It does not return the cell behind. `mazeLit` on the goal returns `[]`. Dead ends are `[]`. `fallbackUsed` is false.

### Older build

For each grid size in the band list, restart `makeRng(seed)` and try up to 40 builds. Accept the first build that passes. If both sizes fail, use the fallback.

One build:

1. `L = rngInt` in the dwell window. `D = rngInt` in the dead-end count window. `goalD = L - D`. If `goalD < 1`, this build fails.
2. Start at a random cell. For up to 80 steps, extend a self-avoiding orthogonal walk.
   - If the current direction has taken fewer than 2 steps and the cell straight ahead is free, the only option is straight ahead. This spacer is what lets co-lit stones sit at Chebyshev distance 2.
   - Otherwise shuffle the free neighbors, then move the straight-ahead neighbor to the front if it is present. Leave the other neighbors in shuffled order.
   - Stop early once the turn-dwell count is at least `goalD` and the number of straight interior cells is at least `D`.
3. While the turn-dwell count is above `goalD` and the path has more than 2 cells, delete the last cell.
4. Fail the build unless the turn-dwell count is exactly `goalD` and there are at least `D` straight interiors. A straight interior is not the start, not the end, and not a corner.
5. Attach `D` spurs, each of length `rngInt` in the band's length window. Walk the straight interiors in shuffled order. From a cell not yet used, try shuffled perpendicular directions, never back along the path. The spur is a straight line of that many free in-bounds cells. Keep the first that fits. Fail the build if any spur cannot be placed.
6. Solution stones are the start, the end, every corner, and every spur attachment. Fail unless `solution stones - 1 === L`.
7. Stone neighbors are the next solution stone along the path and, from an attachment, the spur leaf. Intermediate spur cells are not stones. Fail if any stone has more than 3 neighbors, or if any two neighbors of the same stone have Chebyshev distance under 2.
8. Rush: fail unless at least two spurs have length 3, 4, or 5.
9. Open cells are the path plus the spur cells. Edges are each path step and each spur step, including the step off the attachment. `start` is the first path cell. `goal` is the last. `mazeLit` returns every stone neighbor. The start of a fresh maze lights one stone. A corner lights two. A spur attachment lights three: back, onward, and the spur. Little Pals therefore lights 3 at the fork even though the gaze note says 2. Hiding one of those three either deletes the dead end or traps the token. The check is `<= 3`, every neighbor lit, and no non-neighbor lit.

Seeds 1 and 2 accept inside these caps when the steps and the rng are followed. Do not raise the caps to hide a different rng order.

### Walk

`mazeWalk(from, to)` returns null unless `to` is a stone neighbor of `from`. Otherwise it returns the open cells in order: `from`, the straight interior cells, then `to`. Consecutive cells differ by exactly one row or exactly one column, not both, and that pair is an edge. The polyline does not contain a cell off the edge, so it does not cut a corner and does not cross a wall. A stone two forks away is not a neighbor, so the walk is null. The page `move` of an id that fails `mazeWalk` does not change the token.

### Fallbacks

Used only after the try caps. Each one passes the same checks. Coordinates are `r,c` in path order. Spur lists omit the attachment and follow the open steps.

**Tiny.** Row `(0,0) (0,1) (0,2) (0,3)`. Dwells 3. No spurs.

**Little, 5×5, dwells 6, one spur of length 1.** Path: `0,0 1,0 2,0 3,0 4,0 4,1 4,2 4,3 4,4 3,4 2,4 1,4 0,4 0,3 0,2 0,1 1,1`. Spur off `4,2`: `3,2`.

**Shop, 6×6, dwells 10, spur lengths 2, 3, 3, 2.** Path: `2,2 2,1 2,0 3,0 4,0 5,0 5,1 5,2 5,3 5,4 5,5 4,5 3,5 2,5 1,5 0,5 0,4 0,3 0,2 0,1 0,0 1,0`. Spurs: `4,1 4,2` off `4,0`; `4,3 3,3 2,3` off `5,3`; `1,4 2,4 3,4` off `0,4`; `3,1 3,2` off `2,1`.

### Checks

- `edges.length === cells.length - 1`, and every cell is reachable from `start`. Routes = 1.
- `mazeSolution` is the only start-to-goal stone path, and `solution.length - 1` is inside the band's dwell window.
- Dead-end count and lengths match the table. Tiny has none.
- `mazeLit(start)` has one id on a fresh maze for every band. Every lit id is a stone neighbor. Every stone neighbor is lit, except Tiny, which lights only the successor toward the goal. Lit count is never above the band maximum (1, or 3).
- On Little, `mazeWalk` into the spur leaf returns a polyline that ends on that leaf. `mazeLit` of that leaf contains the branch behind it and does not contain `start` unless the branch is the start.

- `mazeWalk` from `start` to a solution stone that is not the first step returns null. That is the no-teleport check: the token cannot cross a wall or skip a fork.

## What self-check calls

`engineSelfCheck()` returns `{ ok, failures }`. Each failure is one sentence naming the case. The function does not call `Date.now`, `setTimeout`, `setInterval`, `requestAnimationFrame`, `fetch`, `WebSocket`, or `speechSynthesis`. It does not read the DOM. Loops stop at the caps above, so a failed search still returns.

The page `selfCheck` in the architecture memo runs the family cases first. Those call `step` directly. They do not open a socket and they do not arm a timer. After them, the page calls `engineSelfCheck` and merges the failures. It writes the JSON into `#selfcheck-result` and sets the title to `SELFCHECK_OK` or `SELFCHECK_FAIL`. Then it stops.

Call order inside `engineSelfCheck`:

1. `rngUint` four times on `makeRng(1)`. Compare to `0xA087EAF3`, `0x00B349C9`, `0x8706C4EB`, `0xFB2627FD`. Compare `playSeed(1, 1)` to `0x3B230FE8`. `rngInt` on a fresh `makeRng(1)` stays inside a sample range `0..3`.
